# Unity production prompt · Male Dark Elf static character

Use the complete text below as the Unity technical artist's assignment after the [Blender handoff](male-dark-elf-blender-prompt.md). Paths starting with a project folder resolve from `C:/nightcap-development-mmo/`.

## Assignment and inputs

Bring one complete skinned male Dark Elf, his helmet, and his lava-forged armor into the existing **Unity 6000.5.7f1 Built-In** validation project. Produce a reusable prefab and a static inspection scene. Default to **Furnace Warden**. If Blender delivered Last Pour or Ash Requiem, use the matching concept and material cues below. The visible result should resemble an upscaled classic MMO character at normal play distance and survive inspection at portrait distance. Author the presentation without locomotion, animation clips, an Animator Controller, gameplay scripts or camera-control dependencies.

Open `character-production/unity-validation/` at the editor version in `ProjectSettings/ProjectVersion.txt`. Inspect the import settings on `Assets/NightcapHumans/Male_FieldHuman.fbx` and the existing `Assets/NightcapHumans/PaintedCharacter.shader`. The human asset establishes project scale and rig naming. The shader is the established opaque, painted-color baseline for Built-In forward lighting.

Read `character-production/output/dark-elf-male/<suit>/handoff.md`. Import `DarkElfMale.fbx` and its accompanying flattened runtime textures from the same directory. Native paint layers, archive swatches and reference-board images belong in the authoring handoff. Use the supplied atlas that already contains the masked and repainted **project concept image pixels**. Do not substitute a generic store material, an entire concept sheet, or a second projection in Unity. If a required map or binding is missing, identify the exact mesh/slot/file and return that issue to Blender before accepting the prefab.

Use the [Warden plate](../../assets/concept-art/dark-elf/furnace-warden.png), [Last Pour plate](../../assets/concept-art/dark-elf/last-pour.png) or [Ash Requiem plate](../../assets/concept-art/dark-elf/ash-requiem.png) as the matching visual target. Use the [finish study](../../assets/concept-art/dark-elf/armor-finishes.png) for the color roll from cool silver to plum-black. The supplied concept determines the armor silhouette.

## Import and verify the physical character

1. Place new assets under `Assets/NightcapDarkElfMale/<suit>/`. Use subfolders for model, textures, materials, prefab and review scene. Keep generated Unity metadata with the assets. Work on this import and its prefab so changes stay local to the Dark Elf.
2. Start from the accepted male FBX import conventions. Use file units with scale factor 1, then compare Unity world-space height to the Blender handoff. Measure barefoot in base state and equipped in armor state. Use 1 Unity unit per meter, soles at floor level, Y up, character facing +Z, prefab root identity. A 1.82 m source body should measure about 1.82 m in Unity, excluding sabatons and helmet. Investigate any difference greater than 1% against the actual source height. Resolve axis or unit differences at the import/export boundary instead of compensating with a scaled or tilted prefab.
3. Use one **Humanoid** rig with an Avatar created from this model and hierarchical optimization off for inspection. The project male importer is the mapping example. Check the actual Hips, Spine, Head, upper/lower arms, hands, upper/lower legs and feet assignments. Confirm left and right finger chains where supplied. Use the Avatar configuration view to inspect the mapping, then return the character to the authored review stance. Disable animation import. If an Animator is retained for the Avatar, leave its controller empty and root motion off. The scene must present the same character while stopped or playing.
4. Preserve authored normals, smoothing and UV0. Import tangents or calculate a matching tangent basis if a tested normal map was delivered. Preserve four-influence skinning, inspect hierarchy and bind poses, and use the source material-slot order as the remap key. The Warden's eyes, helmet and shoulders should be separate identifiable parts. Each skinned renderer must reference transforms from the one imported skeleton. Check for null bones, duplicate skeletons, inverted faces, dark patches from split normals and collapsed skinned meshes.
5. Save a prefab with stable child names and the armored, helmet-on state active. Set renderer bounds to cover the actual skinned character, including the widest shoulders or tallest crest. Inspect all sides in Scene view and verify the silhouette remains visible near the camera edge. Correct the mesh bounds if they cull early. Use no gameplay colliders, lighting rigs or cameras as dependencies of the character prefab.

## Materials and texture treatment

| Surface | Setup | What must survive in the frame |
| --- | --- | --- |
| Skin and ears | Use the skinned body's supplied sRGB albedo on `Nightcap/Painted Character`, white material tint. Begin with the accepted character settings of diffuse wrap 0.35 and indirect gain 1.5. | Indigo in the shadow, muted violet on the cheek plane, a visible ear rim and a readable jaw with the helm removed. Compare to the base-state Blender render. |
| Eyes, brow and hair | Retain the imported arrangement and source texture assignments. Use the same painted lighting response unless the existing hair material requires cutout at its silhouette. | Amber eyes behind the slots, no flat glowing dots; ivory hair restores cleanly in base state. Check the iris at a grazing angle. |
| Painted plate and underlayer | Use the suit's projected sRGB atlas on the painted shader. Check material tint, UV tiling of 1 and offset of 0. Inspect the texture at full source resolution before changing compression. | Broad bright metal planes taper into plum-black; quilt reads softer and darker. Edges remain beveled when viewed from the side. |
| Recessed heat | The existing painted shader accepts albedo and has no emission input. First check the orange channels using their authored base color alone. For a delivered emission mask, use a dedicated Built-In material on the recessed insert or a suit-local painted-shader variant that adds masked emission to the existing diffuse response. Import the mask as linear data. Keep the intensity adjustable. | Warden has heat behind grille bars and shutters. Last Pour has one channel and bead. Ash Requiem has a hairline of warmth at the mask repair. All three retain shadow detail with bloom disabled. |

Import base color as sRGB with mipmaps. Use the default texture type for color, Normal Map only for actual tangent normals, and sRGB off for scalar masks. Set the maximum texture size to preserve the authored map during first review. Inspect compressed mip levels at distance, especially around visor slits, bright rims and UV borders. Compare the atlas in unlit preview against the same region in Blender. A flipped detail, bright fringe or mirrored asymmetric channel warrants a UV, padding or import fix. A new material cannot correct an inaccurate silhouette.

## Review scene and equipment states

Build a small scene named `DarkElfMale_Review.unity`. Use a matte neutral floor, an unobtrusive gray backdrop, one directional key and adjustable ambient fill. Begin without fog, bloom, a spotlight on the face or auto-rotating objects. Match the concept's eye-level three-quarter camera first. Place the floor so both soles visibly contact it. Use fixed cameras or saved editor views for repeatable comparisons. Keep cameras separate from the prefab.

Create three review states as prefab instances or variants using shared meshes, skeleton definitions and materials. Only one instance should be visible per comparison view.

- **Base.** Full male body, eyes, hair and simple underlayer. Confirm skin at the back, ears, hands and ankles. Compare the facial profile and relative shoulder width to the helmet-off Blender image.
- **Armored, helm off.** All armor except the helm. Restore hair and exposed skin sections according to the handoff. Check gorget clearance, head scale, missing neck triangles and scalp gaps.
- **Armored, helm on.** Default delivery state. Disable only hair and skin sections actually covered by the suit. Check the visible skin through the eye slot, ears through their openings, elbow gaps and exposed neck areas from front, side and back. Restore the other two states without rebuilding the character.

Capture the default state under three static conditions. First use neutral lighting for a source comparison. Then move the key to the opposite side to check that the painted reflection still describes a convex plate. Finally use cool, low-intensity fill with a restrained warm side light, similar to standing near a forge. Record the settings so a reviewer can repeat the frames. Only lighting and camera may differ between these comparisons.

## Acceptance and handback

1. Capture matched front, three-quarter and rear views, a head-and-shoulders close-up, and the fully equipped character framed at roughly 128 screen pixels high in a recorded resolution. Capture the uncovered head once under the neutral light. Compare the same-sized figure against the concept. A Warden needs a square shoulder span, hanging chain and open grille. Last Pour needs one asymmetrical pour lip and a mostly smooth visor. Ash Requiem needs a pale high collar, black crest and long mask.
2. At portrait scale, inspect the eye behind its opening, painted falloff on the cheek or hood, material seams, ear exits and depth behind armor overlaps. At distance, check whether the principal shape remains distinct after fine wear disappears. Use simple directional light and shadow for the comparison. The lower-detail result is an art check, not a hardware benchmark.
3. Reopen the saved scene and prefab after reimport. Verify that the body, helmet and suit still resolve all textures, both feet meet the ground, the hierarchy has one deform skeleton per character, and every renderer binds to it. Confirm zero imported motion clips and no missing scripts, shaders or pink materials on the new assets. Inspect the Console for errors attributable to this import.
4. Deliver the prefab, review scene, materials, textures and their metadata. In the handoff record the Unity version, Blender input revision or hash, source and imported heights, bone and triangle counts, material and skinned-renderer counts, texture dimensions and settings, and screenshots for the states above. Record observed deviations from the concept and any unresolved import defect. A successful handoff establishes a static, skinned character. Movement and performance in a populated game scene are separate milestones.

For importer terminology, consult Unity's [model settings](https://docs.unity3d.com/6000.0/Documentation/Manual/FBXImporter-Model.html) and [rig settings](https://docs.unity3d.com/6000.0/Documentation/Manual/FBXImporter-Rig.html). The installed project's editor and the accepted human import supply the local settings.
