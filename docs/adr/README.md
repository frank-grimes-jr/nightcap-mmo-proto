# Architecture Decision Records

Create ADRs for technical decisions that are expensive to reverse, including engine, language, networking model, database, server authority, asset pipeline, patching, authentication, deployment, persistence, and world-streaming architecture.

Use sequential filenames such as `0001-engine-selection.md`.

Each ADR should contain:

- Title
- Status: Proposed, Accepted, Superseded, or Deprecated
- Date
- Context and constraints
- Decision
- Alternatives considered
- Consequences and risks
- Verification or revisit criteria

Do not delete superseded ADRs. Create a new ADR and link the history.
